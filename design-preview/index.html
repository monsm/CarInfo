第八稿 · 方向「夜航」

同一个界面，四种光

界面本身没有颜色。颜色来自你车此刻所在地的天空 —— 车停在雨里、在黄昏、在凌晨两点，首页就是那个光。
你的车现在怎么样了？这才是车主真正在问的问题，而不是「电池 78%」。

下面是同一个界面在四个时刻的样子：同一套排版、同一个数字、同一个光带，只有光在变。 工艺沿用第七稿的结论没有回退：Inter 200–700 接拉丁与数字、按 SF 字号—字距表排版、车的比例量过 （车长 442 / 车高 136 = 0.308L / 轮径 64 = 0.145L）。

每种光只有一个光源坐标、一组色值与一个「车灯亮度」——上车灯亮度是真实的： 深夜它是唯一光源，所以 100%；正午几乎不需要它，20%。

为什么这次不是换皮

换皮是同一套骨架换颜色。这次是骨架本身在讲事情：

① 车不再是一个图标，而是「你的车现在在哪、那边什么光」的画面；
② 光带把「地平线 / 电量 / 充电进度 / 折线基线」统一成一个形状 —— 这是系统，不是装饰；
③ 巨字压在车身上，把「数据」和「对象」放进同一张画面里，界面不再分成上下两块。

一份车的定义，四种光

整个页面里车只有一份 SVG 定义（<defs> 里的 #car）， 四屏用 <use> 复用；四种光通过 CSS 变量注入： --tint 以 screen 混合打在金属上、--rim 是轮廓光色、 --lampA 是车灯亮度。

这意味着落到 Swift 侧时，车也只需要实现一次，光是一个参数。

动效：仍然只有一次

① 车从下方 10pt 升起淡入（车醒了）② 光带从 0 长到位。没有呼吸、没有常驻发光、没有粒子 —— 停在静止画面时它是一张产品照。

遵守 prefers-reduced-motion。

可以再往上加一层：让光随你车所在地的真实时间缓慢漂移（90 秒一个循环）， App 就真的「活」在你的当下 —— 这是这个方向天然能长出来的东西。
