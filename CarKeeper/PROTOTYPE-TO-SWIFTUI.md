# 原型 → 真机：还原度评估与实施计划

> 对象：`design-preview/stack.html`（1633 行，六页 + 七种叠法 + 相机式底部条）
> 目标：把它变成 `CarKeeper/` 里能跑的 SwiftUI 界面
> 结论一句话：**除「地图底图」一项，其余都能做到肉眼无差；地图底图是硬性做不到的。**
> 而地图恰好是首页 —— 所以那个取舍必须先定，不能等到做完六页才发现。

## 0. 先说为什么不能「100%」

原型里最抢眼的那张地图（180 个城市街区、三级路面、等高线、岸线反光）是**手画的 SVG**。
在真机上它对应的东西是 MapKit 的系统瓦片，而 MapKit 的旋钮只有五个：

地图族（standard / imagery / hybrid）、海拔、**强调度（`.muted`）**、POI 过滤、路况。

**没有任何公开 API 能改道路、街区、水面的颜色。**（本项目 `MapStyleSpec.swift` 里已经逐项核过，
`MAPKIT-FEASIBILITY.md` 记着出处；我这一轮又查了一遍 iOS 26 的 SDK，边界没有变化。）

所以原型和真机之间必然有一处落差，位置和大小是：

| 原型手法 | SwiftUI 对应物 | 还原度 | 说明 |
|---|---|---|---|
| 布局 / 字号 / 间距 / 圆角 | 布局系统 | **100%** | 可以逐像素对齐（HTML 是 390×844 的画布，换成 pt 即可） |
| 卡片弧度 / 错位 / 缩放 | `rotation3DEffect` / `scaleEffect` / `offset` | **100%** | 数值能一一对上（原型里每个都是具体数字，不是"感觉"） |
| 上下消失带（渐隐 + 微弧） | `.mask(LinearGradient)` | **100%** | 原型用的也是 CSS 遮罩，同一个思路 |
| 四角压暗 / 顶部压暗 | `.overlay(RadialGradient / LinearGradient)` | **100%** | |
| 暗玻璃卡 | `.glassEffect(_:in:)` —— iOS 26 的真 API（另有 `GlassEffectContainer`） | **95%** | 系统玻璃是折射 + 反射的物理材质，比 CSS 的 `blur+saturate` 更高级。**它不会和原型逐像素相等，而是同一个档次**——这一项真机会更好看 |
| 车钉 + 朝向锥 + 脉冲光晕 | `Annotation` + 自绘 `Shape` + 相位动画 | **95%** | 钉必须用屏幕空间（`Annotation`），轨迹用地理空间（`MapPolyline`），这条规则已写在 `MapStyleSpec.swift` |
| 吸附（过冲 5~7% + 跟手滞后） | `Animation.spring(duration:bounce:)` 或自写 `CADisplayLink` | **90%** | 能做出来，但 SwiftUI 的 spring 是物理解，原型是解析曲线（easeOutBack）。手感要重新对 2~3 轮 |
| 发光轨迹（柔光晕 + 渐变实线 + 虚线未走） | `MapPolyline` 叠三层 | **85%** | 虚线 dash 在缩放时不好锁屏幕尺寸，会有轻微「爬行」 |
| 罗盘 / 比例尺 | 自绘 | **100%** | 但会和 MapKit 自带的控件打架，要关掉系统的 |
| **地图底图** | 无 | **0%** | 见下 |

## 1. 三件必须先定的事

### 1.1 地图底图走哪条路（唯一做不到 100% 的地方）

**A. 系统底图 + 我们的光** ✅ **已选**
可行、成本 0，`MapStyleSpec` 已经把这层兜住了：把系统瓦片压到 `.muted` 再盖一层蒙版，
艺术感全押在**轨迹、车钉、卡片、光晕**上。
> 补充一个诚实点：我画的那种「城市肌理」在真实地图上本来就不存在 ——
> 我那张图是固定 390×844，它不会被缩放和平移验证。所以 A 不只是更便宜，它**更诚实**。

**B. 可定制瓦片**（MapLibre / Mapbox + 自建 style）
能做出**甚至比原型更好**的底图（真数据、能缩放）。代价：多一个 SDK + 一个 key +
包体 + 审核 + 坐标系（后端报文里是 `coordType: GCJ02`，要转）。

**C. 静态自绘底图**
只有「永远不缩放、且接受位置不真实」时才成立。对「我的车现在在哪」这种应用是致命的。
**不建议。**

### 1.2 纵向叠叠乐的技术路线（决定「吸住」那一下能保留多少）

**甲. `ScrollView` + `.scrollTargetBehavior(.viewAligned)` + `scrollPosition`**
省事，系统负责减速与吸附。**代价：过冲与跟手滞后做不出来**（物理被系统接管），
等于把这一版最要紧的「吸附手感」丢掉。

**乙. 不用 ScrollView，自己用手势 + 偏移量**（和原型一样）
手感能 100% 对齐。但要自己补：滚动惯性、边缘回弹、VoiceOver 三指滚动。工作量约 1.5~2 倍。

**丙. 折中**
`ScrollView` 承载滚动与无障碍，在其上叠一层**视觉偏移**：
用 `GeometryReader` 读真实偏移，把过冲与滞后加在卡片自身的 transform 上。
手感能保住约 80%，工作量 +30%。

> ✅ **已选：乙（完全自管手势）。**
> 这一条选得对，但要先把代价写清 —— 选了乙，下面这六件事就都变成我们自己写，
> 而原型里它们要么是浏览器白送的、要么是我在 JS 里手写的：
>
> 1. **甩出去的惯性**：`DragGesture` 结束时把手指速度交接给弹簧
>    （`Animation.interpolatingSpring(mass:stiffness:damping:initialVelocity:)`）。
>    原型里这段是我在 JS 里手算的（记手势峰值速度再决定翻不翻一张）。
> 2. **边缘回弹**：拖到顶/底时的阻尼与回位。原型里靠 `scrollTop` 的钳位与弹簧。
> 3. **无障碍**：没有 `ScrollView` 就没有三指滚动。必须给卡片栈加两条动作 ——
>    `.accessibilityAdjustableAction`（元素级：上下轻扫 = 上一张 / 下一张）与
>    `.accessibilityScrollAction`（区域级：三指扫），否则 VoiceOver 用户**完全无法翻页**。
>    这是自管手势最大的一笔隐形代价，也是我唯一担心会被漏掉的一条。
>    （2026-09-23 已落地；当时写在这里的名字是 `.accessibilityAction(.scrollUp/.scrollDown)`，
>    而那两个成员不存在 —— 教训是这一条：**计划里的 API 名字同样要对着文档核。**）
> 4. **命中区域**：消失带里的卡片必须退出命中（原型里用 `pointer-events:none`）。
> 5. **下拉刷新/系统手势冲突**：自定义手势要避开屏幕边缘的返回手势。
> 6. **节流**：每帧要重算 N 张卡的 transform。用 `CADisplayLink` 或 `TimelineView`
>    驱动，不能在 `body` 里算（否则每次滚动都会重建 View 树）。
>
> 好处是：原型本来就是「自己管偏移 + 自己跑弹簧」，两边模型**一一对应**，
> 不像丙那样要多一层「读系统偏移再叠一层视觉偏移」的间接。

### 1.3 档位顺序：✅ **已选——地图居中，其余分列左右**

真机 `HomeMode` 的声明顺序需要从 `现在 → 车辆 → 充电 → 车控 → 出行 → 我的`
改成 **`出行 → 车辆 → 现在 → 充电 → 车控 → 我的`**，让「现在」站在正中，与原型一致。
（默认档本来就是「现在」，按 rawValue 取值、不随顺序变 —— 见下面的清单。）
左右不要求等数（现在是左 2 右 3），所以**不需要为了对称去砍功能**。

改动清单（我把调用点逐个查过，比一开始写的准）：

1. **`HomeMode` 的 case 声明顺序** —— 它同时是 `allCases` 的顺序，也就是条子顺序。
2. **`GlobalSearchHUD` 的「去这一档」条目顺序** —— 那份列表是从
   `HomeMode.allCases` 生成的（源码注释里已注明这么做是为了「不然搜索里会静默地少一条」），
   所以排序会跟着变。这是**预期行为**，不是漏改。
3. **`HomeMode.swift` 顶部那段「顺序是按使用的频率排的」注释** ——
   必须一起改，否则就是注释与代码不符（这个仓库最恨的就是这一类漂移）。

**不需要改的两处（我先以为是问题，查过不是）**：

- **默认档**：`MapSpineView` 的兜底值是 `HomeMode.now.rawValue`，按 rawValue 取值，
  与 case 顺序无关 —— 所以默认档依然是「现在」。
- **门禁**：`scan/oneentry.py` 只核对「档位↔页面」「档位↔卡头出现两次」「属于档位的深链零 push」
  **不校验顺序也不校验数量**，所以这次重排不会把 CI 弄红。

- 真机 `HomeMode` 的顺序是 `现在 → 车辆 → 充电 → 车控 → 出行 → 我的`（注释写明「按用的频率」）
- 原型按你的要求把**现在放在正中**（第 3 档），左右各两个

这不是小事：它决定「静止时露三档」时你第一眼看到的是 `出行/现在/充电` 还是 `现在/车辆/充电`，

## 2. 计划（四阶段）

### 阶段 0 · 定稿原型（现在）

产出：**一张逐页规格表**。每个元素的 pt / 字号 / 颜色 / 时长 / 曲线都要有行号可查。
理由：原型里那些「凭手感定的数」——卡间距 20、顶部留白 152、轮子节距 104、过冲 5%、
消失带 150/170、条子静止 200→展开 374 —— 如果不成表，迁移时六页会各写各的。

### 阶段 1 · 原语层（不碰业务）

四个可复用原语 + 一个能并排对照的预览页（挂进已有的 `DevView`）：

1. `GlassCard` —— 玻璃 + 描边 + 顶部高光
2. `ArcStack` —— 错位叠 + 上下消失带 + 过冲吸附 + **自管手势那一整套**（惯性交接、
   边缘回弹、无障碍动作、消失带里退出命中）—— 按已定方案，这块最大，单独排期
3. `DSSwipeStrip` —— **需要重写，不是微调**。现在它是定宽 92pt 的固定形态，
   没有「静止三档 → 按下展开六档」，也没有「透镜跟手 / 整行跟手」这个区别；
   而这两件事是这一版形态的核心
4. `MapCanvas` —— MapKit + 蒙版 + 三层轨迹 + 车钉 + 罗盘/比例尺

验收：四个原语在真机与 HTML 之间**逐项对**（时长、过冲量、间距、透明度）并截图比对。

### 阶段 2 · 六页迁移（一页一页，随时可停）

顺序建议：**现在（地图）→ 出行 → 充电 → 车辆 → 车控 → 我的**。
理由：地图既是首页、又是最可能"做不到"的一页，先做能**最早**暴露不可行；
纯卡片页风险最低，放最后。

每页完成 → 真机截图 → 与 HTML 并排 → 把偏差记进 `REDESIGN-STATUS.md`。

### 阶段 3 · 数据与三态

原型里的数字全是写死的（18.6 km、68%、408 km、七日柱、四段行程）。
真机上每张卡要有 **有数据 / 无数据 / 数据过期** 三态。
`AN` / `VM` 已经算出这些值，所以这一层不是难点、是工作量。
**原型里完全没有这三态 —— 这是最容易漏、也最容易让真机显得比原型难看的一环。**

### 阶段 4 · 手感与性能

- 真机逐项对：拖拽跟手、过冲、吸附、条子展开
- 性能：多张玻璃卡同时挂 material 很贵。策略是**只给可见的卡挂系统玻璃，其余用纯色**。
  要在能跑 iOS 26 的最老设备上测。

剩下的是三件**只能等真机**的事：它们不是没做，是这台机器上量不出来。

### 没做到的：MapCanvas

计划里写了 `MapCanvas` 这个原语，**实际做的是对 `MapSpineView` 的增量修改**，
而不是把它抽出来：

- 做了：行程线加一层更宽更淡的光晕（**只这一点，路线就从「贴在瓦片上的线」
  变成「发着光的路径」**——原型那个观感差主要差在这一层），
  以及巨字头从「固定纸顶」改成「叠叠乐的第一张卡」。
- 没做：把地图抽成可复用原语。地图只在一处（`现在` 那一档），
  抽出来只是为了对称的话，代价（一层间接 + 一团参数）大于收益。
- **底图仍然做不到逐像素对齐**——MapKit 的旋钮只有五个，没有公开 API 改
  道路/街区/水面的颜色（项目里 `MapStyleSpec.swift` 与 `MAPKIT-FEASIBILITY.md` 早就核过）。
  这一条与原型不是「实现得差一点」，是**物理上做不到**。

### 多张玻璃的性能（已补 → 2026-09-25 又删）

曾经的做法是「只给可见的卡挂系统玻璃，其余用纯色」：判定在 `ArcStack.cardView`
（`glassy: abs(tShape) < 0.9`，阈值对准消失带开始变淡的位置），承接在 `GlassCard`
（关掉时走 `TokensPalette.surface`，与玻璃共用同一个圆角矩形）。

**2026-09-25 整条删了**：那个开关的前提是「离阅读线远的卡看不清」（消失带遮罩），
而用户 09-25 第 1 条之后消失带与阅读线都随自管滚动一起删了（见 `ArcStack` 头注）。
留着的后果比性能严重：同一张卡会因为**滚动位置**换材质，滚过去那一瞬正是最像贴图的一刻。
现在每张卡都是同一层玻璃，与它在哪儿无关（`GlassCard` 头注）。
性能这一面要不要再处理（例如用 `LazyVStack` 让屏外的卡不参与），看真机实测。

仍然**不保证**的是「八张卡全在画面里」那种极端态的帧率：
那时可见卡就是八张，该挂的还是都挂着。真机上如果卡，下一步是把阈值往下调，
而不是换掉材质。

### 三态的最后一层：数据时刻（已补）

「无数据」原本就在（`GlassCardEmpty`），缺的是「这份读数是什么时候的」。
补的方式是**给数据源盖时刻**，不是给卡片盖时刻：

- `AppStore.cacheTimes`：键与 `caches` 相同，唯一的写入点是 `saveCache`（它也是
  `caches` 唯一的写入点）。值为空时**同时清掉时刻** —— 留着一个时间戳而值是空的，
  会让卡片显示“有数据但很久没更新”，而真实情况是「这次没取到」，那是两种不同的状态。
- 它**不是 TTL**：不过期、不落盘、不拦请求，只用来在卡头上标一个时间。
- 调用点是「带读数的那几张卡」：充电页的四张同源（`charge`）、
  出行页的汇总（`messages`）、车辆页的档案与车控页的车身（`control`）。
  **没给**的是纯动作卡与纯设置卡（指令 / 一键场景 / 快捷指令 / 设置 / 关于）——
  它们没有会过期的数值，挂一个时间反而是噪音。
- 「我的」页整页没有时间戳：那一页的车辆信息来自登录后的资料，不在 `caches` 里，
  给它一个 `cacheTime` 只会拿到 nil。

### 仍然要真机才能定的三件事

1. **边缘冲突**：自管手势之后，卡片栈自己的竖向拖动与屏幕左缘的返回手势会不会打架。
2. **惯性衔接**：手指离开后系统不再有惯性，速度是手工传给弹簧的 `initialVelocity`
   （`StackSpec.settle(velocity:)`，值 = 峰值速度 ÷ 剩余距离，上限 ±8）。
   转得对不对，浏览器里量不出来。
3. **条子在真实 390pt 下的观感**：截图里的比例是对的，但「三个字露出来多少」这种
   事只能眼睛看。

### 挑叠法的地方（已不存在）

这里原来写的是「`DevView` → 叠叠乐 → 全屏对照页，七种叠法切换，选中的写进
`StackSpec.variantKey`」。2026-09-24 用户把叠法删到只剩一种（吸附堆叠），
2026-09-25 滚动本身也交回系统 —— 对照的对象没有了，七选一、`StackVariant` 与那个
`UserDefaults` 键一起删。入口现在是 `DevView` → 卡片叠 → **卡片叠预览页**，
它留下的理由没变：数字全对的手感与看着对的手感是两件事，后者只能在真机上判。

## 结构对齐（2026-09-23）—— 「没按预览图做」的那一次修正

上一版把六档都做出来了，但**首页不是原型那张图**。把 `design-preview/stack.html` 的
`pageNow()` 逐项列出来对照之后，差集是明确的：

| 原型 `pageNow()` 有的 | 上一版 | 这一版 |
|---|---|---|
| `.map` 全屏地图 | ✅ | ✅ |
| `.plate{left:20;top:62}` 车牌 + 状态点 | ✅（但位置由工具栏让位） | ✅ 安全区下 8pt |
| `.float` **两张**卡（现状卡 + `.card.chips` 四格） | ❌ 三张（多一张图层选择卡）+ 一条常驻操作条 | ✅ 两张 |
| `.compass` 罗盘 | ❌ | ✅ `MapCompass()` |
| `.scale` 比例尺 | ✅ | ✅ |
| 顶部**没有**任何栏 | ❌ 导航栏 + 三枚钮（刷新 / 搜索 / 回到车） | ✅ `.toolbar(.hidden)` |
| 没有光名药丸 / 回到车浮钮 | ❌ 各有一枚 | ✅ 收进车牌徽标的菜单 |

四格的内容也照原型补齐：车速 / 电量 / 胎压 / 车锁，**奇偶上下错开 7px**
（原型 `.card.chips .chip:nth-child(odd){transform:translateY(-7px)}`）。

### 两处有意的偏离（写下来，免得下一个人以为是漏了）

1. **其余五档仍然留一条空标题的导航栏**。原型五页也没有顶栏，但那五档各有一个
   *真的*工具栏动作 —— 车控的语音播报、保养的「添加记录」。把它们一并藏掉就是删功能，
   所以这一轮只还原首页。想彻底对齐，得先把那两个动作搬进卡里。
2. **图层选择从一张卡改成菜单里的一项**。图上仍然是四个图层；换层时浮动首卡
   换成那一层的内容（行程 / 停车 / 充电站），所以功能没少，只是不再占一张卡。

### 顺带删掉的一个入口

`MapQuickBar.swift`（首页那条常驻操作条）**已删**：它的四个动作
（锁车 / 解锁 / 空调 / 寻车）与验 PIN / FaceID 在车控那一档一模一样地存在，
是同一套 `CommandCenter`。首页多一条控制台 = 同一功能第二个入口。
